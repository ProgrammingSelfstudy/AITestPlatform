# 节点通信协议（v1）

唯一来源是 `crates/protocol` 的类型，本文是说明。节点**主动连**服务端（节点不需要公网 IP）。

## 传输

- 控制通道：`wss://<server>/ws/node`，文本帧，JSON。
- 截图和终态页面文字通过 `PUT /api/runs/{run_id}/files/{name}` 上传；WebSocket 里传步骤摘要和文件引用。本机用 HTTP。
- 实时画面：节点在被订阅时通过 WebSocket 发送低帧率 JPEG（≤2 帧/秒），服务端转发给浏览器；没人看就不发。

## 信封

```json
{ "v": 1, "id": "uuid", "type": "run_assign", "ts": "2026-11-20T10:00:00Z", "payload": { } }
```

- `v`：协议版本，不兼容时递增；服务端拒绝过低版本并提示升级节点。
- `id`：消息 id，需要确认的消息用它回 `ack`。
- 收到未知 `type`：记日志并忽略，不断开连接（向前兼容）。

## 连接与认证

1. 节点发 `hello`：`token`（注册时拿到的令牌）、`node_id`（首次为空；之后用 `welcome` 下发的值，重连时带上）、`caps`（节点版本、系统、可用模型来源、是否可看图）、`devices[]`、`running_runs[]`（本地仍在跑或还有未确认上报的 run）。
   - **节点身份密钥** `node_secret`：服务端首次见到某个节点（或给没有密钥的老节点补发）时，在 `welcome` 里下发一次，库里只存 SHA-256 摘要；节点保存到本地状态目录 `node_secret`（权限 0600），之后每次 `hello` 都带上，节点发往平台的 HTTP 请求（取凭证、上传证据）放在 `X-Node-Secret` 请求头里。服务端已给该节点发过密钥时，缺失或不符一律拒绝（WebSocket 回 `unauthorized`，HTTP 回 403），共享令牌不能再冒领别的节点的租约。节点丢了密钥文件需要人工清空该节点的 `nodes.secret_hash` 后重新注册。
   - **节点属主（现在只记名字）** `user_name`：节点启动时的 `NODE_USER_NAME`，**不是机密**，只用来标明「这是谁的节点」「谁在跑」。节点还没有属主时服务端据此登记并绑定；已有属主时必须是同一个名字，否则回 `unauthorized`。浏览器侧用请求头 `x-user-name`（百分号编码）说明「我是谁」：查看谁都能看，改角色、检测、检查本机应用、用节点发任务必须是节点主人。任务和用例等数据是公用的，别人可以用**自己的**节点和额度跑你的数据，不能派到你的节点。系统不防冒用别人的名字。下面是老办法，仍然兼容：
   - **节点属主（老办法）** `user_token`：节点主人的个人令牌（`server create-user --name <名字>` 创建，只显示一次，库里存 SHA-256 摘要），节点从 `NODE_USER_TOKEN` 读取。节点还没有属主时服务端据此绑定；已有属主时必须一致，不一致或令牌无效回 `unauthorized`。发起任务（`POST /api/tasks`，请求头 `x-user-token`）时服务端校验所选节点的属主就是令牌所属用户，否则 403；没有属主的节点谁都发不了任务。
2. 服务端校验令牌，回 `welcome`：`node_id`、`heartbeat_s`（默认 10）、`resume[]`（对每个 `running_runs` 回 `continue` 或 `abort`）。可选字段 `ack_run_updates: true` 表示服务端支持运行上报回执；缺省时走旧协议，不等待回执。
3. 令牌无效：回 `error{code:"unauthorized"}` 后关闭连接，节点不重试。

## 节点 → 服务端

| type | 内容 | 说明 |
|---|---|---|
| `hello` | 见上 | 连接后第一条 |
| `heartbeat` | `devices[]`（serial、状态） | 每 `heartbeat_s` 一次 |
| `device_update` | 设备插拔、状态变化 | 即时 |
| `run_started` | `run_id` | 开启回执时，节点在准备环境或操作设备前发此消息，收到服务端回执才启动执行。启动时间由服务端记录 |
| `step` | `run_id`、`idx`、`tool`、脱敏后的 `args`、`result` 摘要、`file_ref`、`at_ms` | `(run_id, idx)` 幂等，重传安全；`at_ms` 为节点上步骤开始的 epoch 毫秒，旧节点可不发送 |
| `executor_done` | `run_id`、`executor_result`、`reason`、`cost` | 执行员结束 |
| `judge_done` | `run_id`、`final_result`、`items[]`、`judge_status` | Judge 失败时 `judge_status=failed`，**最终结果记 `uncertain`，不顶替** |
| `need_human` | `run_id`、`reason`、`kind`（`danger` / `stuck` / `manual_step`） | 工具层触发，run 暂停等人 |
| `run_blocked` | `run_id`、`blocked_reason` | 如 `setup`、`link`、`stuck` |
| `quota_exhausted` | `source`（`claude_cli` / `codex_exec`） | 额度用完：暂停，**不自动换计费方式** |
| `frame` | `run_id`、JPEG（base64） | 仅被订阅时 |
| `log` | `level`、`msg`（已脱敏） | |

|---|---|---|

### 账号凭证怎么给节点
`run_assign` 的 `lease_id` 为空时跳过登录。收到租约后，节点在 setup 前向本机服务请求 `GET /api/leases/{lease_id}/credentials`，携带 `Authorization: Bearer <节点令牌>` 和 `X-Node-Id`。成功响应带 `Cache-Control: no-store`，响应内的 `account_id` 用作登录态缓存的稳定标识。凭证仅经 stdin 交给 setup，使用后丢弃。

令牌无效返回 `401`，节点头缺失或与 run 的节点不符返回 `403`，租约已取过、已释放或已到期返回 `410`。`needs_cleanup` 为真时先执行 teardown，默认值为 `false`。

### 节点上传运行证据

`PUT /api/runs/{id}/files/{name}` 使用与凭证接口相同的 `Authorization: Bearer <节点令牌>` 和 `X-Node-Id`，节点必须与 run 绑定的节点一致。文件名只允许英文字母、数字、点、下划线及连字符，且不能包含两个连续的点。PNG 截图和 UTF-8 文本每个最多 10 MiB；录屏文件 `rec_01.mp4`、`rec_02.mp4` 等每个最多 150 MiB。run 进入终态后允许补传 10 分钟。成功返回 `204`，同名重传原子覆盖。浏览器使用 GET 读取已登记的证据。

节点每 2 秒读一次 `trace.json`，上报新增步骤并上传对应的操作前观察图和操作后原图。结束时重发步骤并补传剩余截图和 `final_page.txt`。上传失败重试 3 次，最终仍失败时记录日志并继续执行收尾，只上报可读取的 Judge 截图引用。

执行员结束后，节点在独立判定开始前上传录屏；取消或崩溃时也尝试补传已收尾的分段。随后用相同认证调用 `PUT /api/runs/{id}/recording-index`，发送 `{"segments":[{"seq":1,"file":"rec_01.mp4","start_epoch_ms":1700000000000,"duration_ms":170000}]}`，只提交上传成功的分段。服务端在同一事务中补齐已登记 MP4 的时间字段；重复请求幂等，任一分段未登记返回 `409`，不写入部分数据。索引 JSON 不作为文件对外提供。

`GET /api/runs/{id}` 的 `recordings` 按 `seq` 排序，返回 `url`、`size` 和两项时间字段（索引未送达时为 `null`）。用 `run_steps[].at_ms` 找到满足 `0 <= at_ms - start_epoch_ms < duration_ms` 的分段，再跳到视频的 `(at_ms - start_epoch_ms) / 1000` 秒。两段之间的拉取间隙或旧步骤没有可定位的画面。录屏 GET 支持完整响应及单个字节区间；非法区间返回 `416`。

## 断线与恢复

- 节点：指数退避重连（1s、2s、4s … 上限 30s，带抖动）。未确认的运行上报用原消息 ID 留在节点进程内存；重连获准继续才按原顺序补发。已经在断线期间跑完但未上报终态的 run 也参加恢复。待确认消息 30 秒没有收到回执时主动重连；节点进程退出不会保留本地进度。
- 服务端：连接中断或 `3 × heartbeat_s` 未收到消息时标记设备离线；未启动的 `assigned` 退回队列，`running` / `judging` 进入 `node_lost`。服务端重启也按相同规则恢复。默认宽限 120 秒；超过宽限或原节点没报本地进度则判 `blocked`（`blocked_reason=node_lost`），释放设备和租约，租约标脏以便下次先清理。已取消的执行不会恢复。
- 启动回执丢失时，只接受同一消息 ID 重传；已启动的 run 不接受另一条启动申请。`step` 按 `(run_id, idx)` 去重。数据库暂时无法保存上报时服务端断开连接，等待节点补传。旧连接结束不把已重连的新连接设为离线。

## 版本与兼容

- 只增加可选字段不升版本；改字段含义或删字段才升 `v`。
- `crates/protocol` 里每种消息都要有 serde 往返测试，且对未知字段容忍。
