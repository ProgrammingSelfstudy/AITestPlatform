# 数据模型（P0–P2）

数据库：PostgreSQL。主键一律 `uuid`；时间一律 `timestamptz`；JSON 字段用 `jsonb`。
文件（截图、录屏、轨迹）存文件系统，库里只存元数据，路径经存储接口封装，后期可换 MinIO。

## 关系总览

```
users ─┬─< projects ─┬─< test_cases
       │             └─< test_accounts ─< account_leases
       └─< nodes ─< devices
projects ─< tasks ─< runs ─┬─< run_steps
                           ├─< judge_items
                           ├─< files
                           └─< reviews
runs >─ test_cases / nodes / devices / test_accounts
```

## 表

### users
`id`、`username`（唯一）、`password_hash`（argon2）、`role`（`admin` / `member` / `reviewer`）、`created_at`。

### projects
`id`、`name`、`created_by`、`created_at`。

### nodes（执行节点，一台电脑一个）
| 字段 | 说明 |
|---|---|
| `owner_user_id` | 节点归属人。**任务只能派到发起人自己的节点** |
| `name` | 节点名 |
| `token_hash` | 节点令牌的哈希，令牌只在注册时显示一次 |
| `status` | `online` / `offline` |
| `last_seen_at` | 最近一次心跳 |
| `caps` | `jsonb`：节点版本、操作系统、可用模型来源（`claude_cli` / `codex_exec`）及是否可看图 |

### devices
`id`、`node_id`、`serial`、`platform`（第一期只有 `android`）、`model`、`os_version`、`screen_w`、`screen_h`、`bottom_shift`（底部坐标偏移，见 PoC 的 `config.yaml`）、`status`（`idle` / `busy` / `offline`）、`last_seen_at`。唯一键 `(node_id, serial)`。
设备占用锁：同一设备同一时刻只跑一个 run，用 `runs` 上的部分唯一索引保证（见下）。

### test_cases
| 字段 | 说明 |
|---|---|
| `project_id`、`code` | 用例编号，如 `TC-04`，项目内唯一 |
| `title`、`level` | 标题、难度 |
| `preconditions` | `jsonb` 数组 |
| `steps` | `jsonb` 数组 |
| `expected` | `jsonb` 数组，每项 `{idx, text}`，Judge 逐条判定 |
| `data` | `jsonb`，用例数据；账号用占位符 `{{account.xxx}}`，**不存明文** |
| `should_fail` | 故意写错的负例，正确判定必须是 `failed` |
| `status` | `active` / `blocked` / `archived` |
| `version` | 用例修改自增，run 记录当时的版本 |

### test_accounts（账号池）
`id`、`project_id`、`env`（`debug` / `release`）、`tags`（如可开语聊房）、`username_enc`、`password_enc`（AES-GCM，主密钥放环境变量或文件，不入库）、`status`（`idle` / `leased` / `cooling` / `quarantined`）、`health jsonb`（最近探针结果）。
**API 永不返回 `*_enc`**；明文只通过一次性、仅限节点令牌的接口发给执行节点，且不写日志。

### account_leases
`id`、`account_id`、`run_id`、`device_id`、`owner_user_id`、`acquired_at`、`heartbeat_at`、`expires_at`（TTL）、`released_at`、`dirty`（释放时环境没恢复干净则置位并转 `cooling`）。
规则：一个账号同一时刻只有一条未释放租约；一个账号只登录在一台设备上；每用户并发上限由配置给出。

### tasks
一次发起的执行：`id`、`project_id`、`created_by`、`case_ids`、`role_config`（`jsonb` 快照：执行员/Judge 用哪个来源哪个模型）、`status`、`created_at`。

### runs（一条用例的一次执行）
| 字段 | 说明 |
|---|---|
| `task_id`、`case_id`、`case_version` | |
| `node_id`、`device_id`、`account_id` | 派发时确定 |
| `executor_role`、`executor_model` | 如 `executor` + `gpt-6.2-astra` |
| `status` | `queued` → `assigned` → `running` → `judging` → `finished`；异常终态 `blocked`、`cancelled`；节点掉线为 `node_lost`（宽限期内可恢复） |
| `executor_result` | `passed` / `failed` / `uncertain` / 空 |
| `judge_status` | `completed` / `failed` / `not_run` |
| `final_result` | `passed` / `failed` / `uncertain` / `blocked`；**Judge 没跑成时不得用执行员自评顶替** |
| `blocked_reason` | 如 `setup`、`link`、`node_lost`、`stuck`，统计完成率时区分链路/环境故障 |
| `executor_reason`、`cost jsonb`、`started_at`、`finished_at` | |

约束：
- 部分唯一索引 `unique(device_id) where status in ('assigned','running','judging')`：设备占用锁。
- 派发队列：`select … from runs where status='queued' … for update skip locked`。

### run_steps
`run_id`、`idx`（唯一键 `(run_id, idx)`，保证重传幂等）、`tool`、`args`（`jsonb`，**已脱敏**）、`result`（`jsonb` 摘要）、`file_ref`（该步截图引用）、`ts`（服务端入库时间）、`at_ms`（节点上步骤开始的 epoch 毫秒，旧步骤为空）。

### judge_items
`run_id`、`idx`（对应用例预期条目）、`expected_text`、`verdict`（`passed` / `failed` / `uncertain`）、`evidence`、`file_refs`。证据不足一律 `uncertain`。

### files
`id`、`run_id`、`kind`、`path`、`size`、`sha256`、`created_at`。节点上传截图用 `shot`，终态文字用 `page`，路径为数据目录下的 `files/{run_id}/{name}`。旧类型继续保留。录屏沿用 `recording`，以 `seq` 标识分段，`start_epoch_ms` 和 `duration_ms` 在上传录屏索引后补齐（可以为空）。`shot` / `page` / `recording` 的同一路径不区分大小写且只登记一次。

### reviews

| 字段 | 说明 |
|---|---|
| `id`、`run_id` | UUID 主键、外键；仅 `finished` 的 run 可提交 |
| `item_idx` | 空表示整条用例；否则必须是同一 run 已存在的 `judge_items.idx` |
| `mark` | `correct`（Judge 判对）、`passed`（应为通过）、`failed`（应为失败） |
| `judge_verdict` | 提交时由服务端快照：逐条取 `judge_items.verdict`，整条取 `runs.final_result` |
| `note`、`reviewer` | 可选备注最多 2000 个字符；审核人姓名为 1～32 个字符的非空文本，不含控制字符，没有用户表外键 |
| `created_at` | 服务端写入时间；历史保留，`current_reviews` 每个 `(run_id, item_idx)` 取一条，按时间倒序、同时间按 `id` 倒序决胜 |

- `GET /api/runs/{id}/reviews` 返回 `history` 和 `current` 两个数组；`POST` 追加，不覆盖历史。审核不改变 run 的 Judge 结论与最终结果。
- 统计和 JSON Lines 导出只读 `current_reviews`。混淆矩阵的 `correct` 在人工轴上换成快照值；判对率仍只数 `mark='correct'`，未审核时为 `null`。
- 导出使用 run 的用例码、用例版本和预期快照。整条用例的预期和逐条 Judge 证据分别合并成文本。文件引用仅保留安全文件名；可从证据引用定位时，`recording_position` 给出首个可定位的步骤编号、分段号和段内秒数。`has_recording` 表示有已登记的录屏分段，不表示每一步都能定位。

## 指标口径（与 PoC 验证报告一致）

- 完成率 = `executor_result` 非空的 run ÷ 总 run，不含 `should_fail` 之外的受阻用例；`blocked_reason` 为 `link` / `setup` / `node_lost` 的单独列出，不能只报排除后的数字。
- 判定准确率 = 已核对且 `mark='correct'` ÷ 已核对；误报 = 判过但人工说应失败；漏报按 `should_fail` 用例判过的比例另算。
- 核对未过半且不足 30 条时，看板必须标注「样本不足，只作参考」。

## 安全约定

- 密码 argon2；账号密文 AES-GCM；节点令牌只存哈希。
- `run_steps.args`、日志、轨迹、报告里出现账号或密码一律替换为占位符；入库前统一过一遍脱敏。
- 审计：谁在何时申请、使用、释放了哪个账号，单独写审计表（P3 补）。
