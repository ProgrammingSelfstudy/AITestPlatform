# 前端 UI 改版需求（交给 Gemini）

## 1. 背景与目标

AI 测试平台：执行节点连着 Android 真机，AI 执行员按用例步骤操作手机，独立 Judge 逐条判定预期，最终给出「通过 / 失败 / 待人工确认 / 受阻」。

现有 `web/` 已经能用，但是功能堆叠、观感粗糙。本次**只改界面的外观、布局和交互**，目标是做成一个专业、克制、信息密度合适的测试平台后台：测试人员一眼看出「哪些过了、哪些没过、哪些要我确认」。

## 2. 硬性约束

1. 技术栈固定：React 19 + TypeScript + Vite + Ant Design 6。不引入别的 UI 库，图表或图标另需库须先说明理由。
2. **不改后端接口，不改 `web/src/api.ts` 里的类型和函数签名**（例外：`/api/models` 和创建任务的请求体已改成按角色选择，见 `docs/落地记录.md` 的「角色与模型配置」一节）（可以新增前端辅助函数）。所有数据来自现有接口：`/api/nodes`、`/api/models`、`/api/projects/*`（用例列表）、`/api/tasks`、`/api/tasks/:id`、`/api/runs/:id`、`/api/runs/:id/reviews`、`/api/reviews/stats`、`/api/reviews/export`。
3. 路由保持 hash 路由：`#/nodes`、`#/tasks`、`#/tasks/:id`、`#/runs/:id`，其他地址显示「找不到这个页面」。
4. **没有登录页**。写操作（发起、取消、提交审核）用现有的口令弹窗：口令只放在 `x-review-token` 请求头，**不得进 URL、日志、`localStorage` 明文展示**。
5. **界面文案全部中文**，代码注释中文。
6. 凭证安全：界面任何位置都不显示账号密码。步骤文字里的 `{{account.xxx}}` 占位符原样显示，不要替换。
7. **判定不能美化**：失败就是红色「失败」，待人工确认就是「待人工确认」，不得把它们显示成通过或用绿色。受阻要和失败区分开。
8. 同时支持浅色、深色（跟随系统）。宽度 1280 以上为主，窄屏（≥ 768）不崩，不要求手机适配。
9. 可访问性：状态不能只靠颜色，必须有文字或图标；键盘可操作；对比度达到 WCAG AA。
10. 完成后 `pnpm build`（含 `tsc -b`）必须零错误零警告通过。

## 3. 视觉方向

- 风格：冷静、专业的工程工具感，参考 Linear / Vercel Dashboard 的克制。**不要**花哨渐变、大插画、玻璃拟态。
- 基础：以 Ant Design 主题 token 驱动（`ConfigProvider` 统一配置圆角、主色、字体），不要到处写死颜色；自定义样式集中在 `styles.css`，用 CSS 变量。
- 字体：中文用系统字体栈；ID、序列号、命令、路径用等宽字体。
- 状态色约定（浅深色都要调到可读）：

| 状态 | 颜色语义 | 文案 |
|---|---|---|
| passed | 绿 | 通过 |
| failed | 红 | 失败 |
| uncertain | 琥珀 | 待人工确认 |
| blocked | 灰蓝 | 受阻（后跟原因） |
| running / judging | 蓝，带动效 | 执行中 / 判定中 |
| queued / assigned | 中性灰 | 排队中 / 已分配 |
| cancelled | 灰 | 已取消 |
| node_lost | 橙 | 节点掉线 |

- 间距按 4 / 8 / 16 / 24 的节奏；列表行高紧凑；空状态、加载骨架、错误态都要设计，不要只有白屏或一个 spin。

## 4. 页面需求

### 4.1 全局框架
- 顶部或左侧导航：「节点与设备」「任务」，当前页高亮（任务详情、运行详情都归「任务」）。
- 右上角：深浅色切换、口令状态（已设置 / 未设置，点击可重设或清除）。
- 页面标题、面包屑：`任务 / 任务 xxxx / 运行 TC-04`，可点回上级。

### 4.2 节点与设备（`#/nodes`）
- 每个节点一张卡片：节点 ID（缩写，可复制）、在线 / 离线、节点版本、系统、模型来源（claude_cli / codex_exec，标是否支持视觉）、最后在线时间（相对时间，悬停显示绝对时间）。
- 节点下列出设备：序列号、型号、系统版本、分辨率、状态（空闲 / 忙碌 / 离线）。
- 离线节点整体降低视觉权重；顶部汇总「在线节点 N / 空闲设备 M」。
- 自动轮询刷新（沿用 `usePolling`），刷新时不闪烁、不丢失滚动位置。

### 4.3 任务列表（`#/tasks`）
- 表格列：任务 ID、项目、节点、执行员模型、Judge 模型、创建时间、**结果概览**（如「3 通过 · 1 失败 · 1 待确认」，用小色块条或分段进度条表示，一眼看比例）、进行中数量。
- 支持按项目、结果状态筛选，按时间排序；有进行中的 run 时行上有动效标记。
- 右上角主按钮「发起任务」，打开发起弹窗（见 4.4）。
- 页头显示审核统计：已审核数量、Judge 判定正确率（`/api/reviews/stats`，没有数据时显示「暂无」），并提供「导出训练数据」按钮。

### 4.4 发起任务（弹窗或抽屉）
- 步骤：选节点（只能选在线的，离线置灰并说明原因）→ 选项目 → 选用例（多选，带搜索、全选；每条显示编号、标题；`should_fail` 的负例带「故意失败」标签；状态非可用的用例置灰并显示原因）→ 选执行员模型和强度、Judge 模型。
- 模型下拉的选项和默认值来自 `/api/models`，**前端不写死任何模型名**。
- 规则提示（要展示出来）：任务只能在发起人自己的节点上、用自己的模型来源执行；额度用完会暂停并通知，不会自动换计费方式。
- 提交前显示摘要（N 条用例、节点、模型）；提交中按钮 loading，失败显示后端原始错误，不吞。
- 需要口令时先弹口令框，成功后继续提交，不丢用户已填内容。

### 4.5 任务详情（`#/tasks/:id`）
- 头部：任务基本信息（节点、模型、创建时间）+ 结果分段条。
- run 列表：用例编号 + 标题、状态、**最终结果**、执行员自评、Judge 状态、设备序列号、耗时、开始时间；点击进入运行详情。
- **执行员自评与 Judge 结论不一致时，行上加醒目提示**（比如「自评与 Judge 不一致」徽标），这是最需要人看的。
- 进行中的 run 支持「取消」（二次确认，需口令）。

### 4.6 运行详情（`#/runs/:id`）——最重要的一页
布局建议左右分栏，左侧过程、右侧结论；宽屏下两栏各自滚动。

1. **顶部摘要条**：最终结果大徽标、用例编号和标题、状态、设备、模型和强度、耗时、工具调用数；受阻时显示原因；与自评不一致时的警示。
2. **预期与 Judge 判定**：每条预期一行——预期原文、判定（通过 / 失败 / 待人工确认）、证据文字、引用的截图缩略图（点击放大，大图上标注是第几步）。证据里引用 `step:N` 的，可点击跳到对应步骤。
3. **执行步骤时间线**：每步显示序号、动作（中文化：点击 / 滑动 / 输入 / 等待 / 观察…）、目标文字或坐标、新出现的页面文字、「操作前 / 操作后」截图缩略图。运行中新步骤自动追加，用户滚动阅读时**不要强行滚到底**，只提示「有 N 个新步骤」。
4. **录屏回放**：已有 `RecordingPlayer`，按分段 MP4 顺序播放；点击步骤跳转到对应时间点（用 `at_ms`）；找不到时间点时显示原因，不影响手动播放。
5. **人工审核**（已有 `RunReviews`）：对整体或某一条预期标记「Judge 判对 / 应为通过 / 应为失败」，可填备注和审核人；显示历史记录与当前有效记录；提交需口令。
6. 执行员给出的原因（`executor_reason`）折叠展示。
7. 运行中自动刷新，结束后停止轮询。

## 5. 通用交互要求
- 所有时间显示本地时区，相对时间 + 悬停绝对时间。
- ID、序列号一键复制，复制后有轻提示。
- 所有请求失败：显示可读错误和「重试」，保留后端返回的原始错误文字。
- 加载用骨架屏，不要整页转圈；轮询刷新不要触发整页重渲染闪烁。
- 大图查看支持键盘左右切换、Esc 关闭。

## 6. 不在范围内
- 登录、注册、用户管理页面。
- 新增后端接口或改数据结构。
- 手机端适配。
- 用例编辑器、脚本生成页面（以后再做）。

## 8. 交付方式
- 只改 `web/src/` 下的文件，不动 `crates/`、`migrations/`、`docs/`。
- 保持现有文件拆分（`NodesPage`、`TasksPage`、`RunPage`、`RunReviews`、`RecordingPlayer`、`NewTaskDialog`），可以拆出新组件，不要合并成大文件。
- 交付时给出：改动文件清单、截图（浅色 / 深色各一张运行详情页）、`pnpm build` 的输出。
